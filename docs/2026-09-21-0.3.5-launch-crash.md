# 0.3.5 crashed at launch: the sequence, the cause, the fix, the gate

All times UTC, 2026-09-20/21. Sources: the release runs, the PRs, the
maintainer's app log, the community API's manifest.

## Sequence

| when | what |
|---|---|
| 20:53 | v0.3.5 tagged on main (80beb0d) after the maintainer flew the dev build. |
| 21:30–22:11 | Release run: tests, deny, signed Windows and Linux builds, deploy. Every job green. The manifest serves 0.3.5. |
| 23:45:13 | The maintainer's installed 0.3.4 starts, sees 0.3.5, installs it. |
| 23:45:42, 23:45:56, 23:46:51 | 0.3.5 starts three times. Each writes "starting" and "voice discovered" to the log and nothing more. No panic text anywhere: a GUI process has no stderr. |
| 23:46:54 | The dev build (debug) starts and runs normally. |
| 23:47:59 | "why does the prod app immediately crash?" |
| 23:53 | Cause found and PR #137 opened (see below). Version 0.3.6. |
| 00:03 | Yank: the manifest is rewritten by hand to 0.3.4 with the 0.3.4 installers and signatures; the 0.3.5 installers are deleted from the server; the maintainer deletes the 0.3.5 GitHub release. |
| 00:23 | #137 merged (a GitHub API slowdown made the merge look stuck for some minutes). |
| 00:24–00:57 | v0.3.6 tagged; release run green; the manifest serves 0.3.6. |

Exposure: about 1 h 50 min between the 0.3.5 manifest going live and the
yank, during which any 0.3.4 install that checked for updates took 0.3.5
and stopped launching. Those installs cannot reach their own updater (the
check runs after setup) and need the 0.3.6 installer by hand; the 0.3.6
notes say so.

## Cause

`tauri_plugin_deep_link::init()` (the Frontier account link's `edda://`
callback) was registered under `#[cfg(debug_assertions)]` — a leftover
from the deep-link spike, where a dev build also registers the URL scheme
at runtime while the installer does it for a release. The guard went on
the whole plugin, not just the scheme registration. `setup()` called
`app.deep_link()` in every build, and Tauri's `state::<T>()` panics on a
type nobody managed. So every release binary of 0.3.5 panicked in setup,
after "voice discovered" and before "overlay ready"; every debug binary
had the plugin and was fine.

## Why the gate missed it

"The boss flies before we ship" is a debug-build flight. A
`cfg(debug_assertions)` divergence at start-up is invisible to it by
construction, and the release run built and signed the binary without
ever launching it. Tests passed because none of them build a Tauri app.

## Fix (0.3.6, #137)

The plugin is registered in every build; only the runtime scheme
registration stays debug-only. One line. The audit found no other
`cfg(debug_assertions)` at start-up.

## Never again

1. **A panic is written down.** `lib.rs` installs a panic hook right after
   logging starts: the location and message become the last line of
   `edda.log`, given 300 ms to reach the file before the default hook
   aborts. The three silent deaths above would have read `PANIC: … state()
   called before manage() for tauri_plugin_deep_link::DeepLink`.
2. **The release binary is launched before it ships.**
   `scripts/smoke-launch.sh` runs the built binary with `EDDA_SMOKE_EXIT`
   set; `setup()` runs to its end, logs "smoke: setup complete", and the
   app exits 0 a few seconds later. The script fails on a non-zero exit, a
   timeout, or a log without that line (exit 0 alone is not proof: a
   second instance exits 0 by handing off to the first). `release.yml`
   runs it on the signed Windows binary and, under Xvfb, on the Linux one,
   before either artifact uploads — so nothing that dies in setup can
   reach the manifest.
3. **The harness is proven on every PR.** `ci.yml` builds the debug binary
   and runs the same script on Windows and Ubuntu, so a broken harness is
   found on a PR, not on a release.

What this does not cover: a crash after setup (in a window, a job, a
command) and anything that needs a journal. Those stay with the flight,
which also runs the debug build; the measure of this gate is that a
release binary that cannot start cannot be released.
