The ship computer

EDDA works without any AI model: routes, trade, callouts, the HUD and the voice all run on their own. Hook a model up and you get a ship computer you can talk to — one that answers from your own journal and the community data, tells you where each fact came from, and can put its hands on the controls.

The model runs on your account, with your key, under your choice of provider — including one on your own machine. Nothing you say to it passes through EDDA's server, and EDDA never sees your key. What EDDA collects.

What it gets you

Ask in plain language, typed or by voice. The model does not guess: it is handed a library of small tools that read your journal and query the community API, and every answer says whether a fact is first-hand from your journal or community data with an age on it.

  • Your ship and your fleet — status, fuel, cargo, modules and their engineering, where every ship you own is stored, your fleet carrier's position and tritium.
  • Engineering — what you hold, which engineers you have unlocked and how to unlock the rest, blueprints for a module type, the materials still missing for a grade, a shopping list across material traders, where to farm each material, synthesis recipes.
  • The galaxy — how far a system is, what is in it, the nearest station with a given service, systems around you with Powerplay control, a station's full price board, a search for a commodity, module or ship, and the profit finder ranked by credits per hour.
  • Routes — plot a jump route, read the one in your galaxy map hop by hop, plot and follow a fleet-carrier route, order your mission hand-ins.
  • Your record — ranks, combat statistics, missions and their progress, Powerplay merits calibrated from your own sales.
  • Hands on the controls — press your own game bindings (gear, scoop, next target…), set the power distributor to an exact split, start or stop following a route, choose which signal sources get announced, and say a line aloud in the ship's voice.

With Claude, research can be switched on: questions about game mechanics are searched on the web and answered with citations. That is the only provider with it, and it is never used on anything from your own data.

Check ship computer in Settings runs a fixed set of cockpit questions against whatever you have connected and scores the answers against your journal. It presses nothing in the game and says nothing aloud. Run it after connecting a new model: a pass means the model used the tools instead of guessing.

Connecting a model

Settings → Ship computer. Pick a service or a local server, choose from the list, paste a key where one is needed, and press Check. Keys go into your operating system's credential store (Windows Credential Manager, the Secret Service on Linux), never into a file EDDA writes.

Claude (Anthropic)

  • Create a key at console.anthropic.com (API Keys). Paste it as the key; leave the model blank for the default, or name one.
  • The only provider with web research. Uses Anthropic's own API rather than the OpenAI-style one, so it is its own entry in the list.

OpenAI

  • Key from platform.openai.com. Preset endpoint https://api.openai.com/v1, default model gpt-4.1-mini; any current chat model with tool calling works.

Mistral

  • Key from console.mistral.ai. Preset endpoint https://api.mistral.ai/v1, default model mistral-small-latest.

Groq

  • Key from console.groq.com. Preset endpoint https://api.groq.com/openai/v1, default model llama-3.3-70b-versatile. Very fast; a good fit for voice.

OpenRouter

  • Key from openrouter.ai. Preset endpoint https://openrouter.ai/api/v1, default model mistralai/mistral-small-3.2-24b-instruct:free, which costs nothing. One key reaches many models; pick one whose OpenRouter page lists tools under supported parameters.

Grok (xAI)

  • Key from console.x.ai. Preset endpoint https://api.x.ai/v1, default model grok-4.6. xAI serves the OpenAI-style chat API with tool calling beside its own; EDDA speaks the former.

Ollama (local)

  • Install from ollama.com, then in a terminal: ollama pull qwen3:8b. Ollama serves an OpenAI-compatible endpoint at http://localhost:11434/v1, which is the preset; no key.
  • Pick a model whose library page carries the tools tag. qwen3:8b is the default because it is the smallest one that reliably calls the tools; a 14B or larger model does better still.

LM Studio (local)

  • Install from lmstudio.ai, download a model marked for tool use, and start the local server (the Developer tab). The preset endpoint is http://localhost:1234/v1; enter the model's identifier as shown in LM Studio; no key.

Any other service or server

Choose Other service or Other local server and fill in the endpoint and model yourself. What EDDA needs from it:

  • The OpenAI chat-completions API at <endpoint>/chat/completions, with the key sent as a bearer token if one is set. vLLM, llama.cpp's server, LocalAI, text-generation-webui, Together, Fireworks, DeepSeek and most others serve it.
  • Tool calling (also called function calling). This is not optional: the ship computer answers by calling tools, and a model or server that cannot return tool_calls will answer from thin air or fail. Check both the server and the specific model; a server can support tools while the model you loaded does not.
  • Context of at least 8k tokens. The tool catalogue alone is about 5k tokens. Local servers often default to less; raise it in the server if answers come back truncated or the model forgets the question.
  • A model of 8B parameters or more for local use. Smaller ones tend to call the wrong tool or none.

What travels, and to whom

When you ask something, EDDA sends your question, the tool catalogue and, as the model asks for them, the tool results — which means facts from your journal (your ship, where you are, what you carry) go to the provider you chose, under your account. With a local server they never leave your machine. EDDA's own server is not in the loop at all. Providers bill by the token; a cockpit question is a few thousand tokens in, a few hundred out.
